# 对端动态标签规则使用 ipset

## 背景

对端远端防火墙的动态标签规则当前按标签有效成员展开为多条 `-s IP -j ACTION` 规则。用户数量增长时，远端链长度和每次成员变更的 SSH 写回量会随成员数增长；这与中心防火墙已经采用 ipset 的方式不一致。

同时，标签删除保护已经覆盖中心规则和对端引用，但没有阻止仍关联用户或组的标签被删除。

## 目标

- 对端动态标签来源使用对端本机独立的 `hash:net` ipset。
- 同一标签在同一对端被多条逻辑规则引用时复用一个集合。
- 标签成员变化时重建完整期望集合，不使用只增不减的增量追加。
- 先准备集合，再原子替换 iptables 用户链；成功后回收旧集合，失败时保留旧链。
- 对端首次使用标签规则且缺少 ipset 时，Debian/Ubuntu 与 RHEL 系自动安装依赖。
- 删除对端时清理 NiceVPN 为该对端创建的标签集合。
- 只有没有用户/组成员、中心规则、Mesh 路由和远端防火墙引用的标签才允许删除。

## 非目标

- 不改变中心防火墙现有 ipset 命名和 reconcile 机制。
- 不反向解析任意手工 iptables 规则来恢复标签语义。
- 不接管对端其他应用创建的 ipset 集合。
- 不在本次变更中重构对端全部系统防火墙持久化机制。
