# Spec Delta

## Purpose

为 VPN 运维后台提供统一、可复用且可验证的页面外壳、视觉语言与交互反馈，使所有功能页面在桌面和窄屏环境下保持一致、清晰和可操作。

## ADDED Requirements

### Requirement: 统一后台外壳
系统 SHALL 为所有已初始化的管理页面提供一致的侧边导航、当前页面标识、页面标题区域和内容区域，并保持既有页面 URL 可用。

#### Scenario: 从侧边导航切换页面
- **WHEN** 管理员点击任一导航项
- **THEN** 系统进入对应的既有 URL，并明显标识当前导航项

#### Scenario: 打开子页面
- **WHEN** 管理员打开对端部署说明等子页面
- **THEN** 系统保持后台外壳，并标识其所属的一级导航模块

### Requirement: 响应式可操作布局
系统 SHALL 在常用桌面宽度和窄屏宽度下保持主要内容、导航、工具栏、表格和对话框可访问，不得依赖水平页面滚动才能触达主要操作。

#### Scenario: 窄屏访问功能页
- **WHEN** 可视区域不足以同时展示固定侧栏和主内容
- **THEN** 导航可收起或临时展开，主要操作仍可见或可从明确的溢出菜单访问

#### Scenario: 工具栏空间不足
- **WHEN** 页面操作按钮无法在一行内完整展示
- **THEN** 系统换行或收纳低频操作，不遮挡搜索、主操作和批量操作状态

### Requirement: 统一视觉主题
系统 SHALL 使用一致的深色科技风主题，统一品牌色、状态色、间距、圆角、边框、字体层级和数据字体，并保证正文、控件与状态提示具有足够的可读性。

#### Scenario: 展示业务状态
- **WHEN** 页面展示运行、停用、警告、失败或未知状态
- **THEN** 系统使用统一的文字、图标和状态色表达，且不只依赖颜色传达含义

#### Scenario: 展示 IP 与规则数据
- **WHEN** 页面展示 IP、CIDR、端口、证书序列号或规则表达式
- **THEN** 系统使用一致的数据字体和可复制呈现方式

### Requirement: 统一操作层级
系统 SHALL 将操作区分为主操作、普通操作、行操作、低频操作和危险操作，同类操作在所有页面使用一致的位置、文案和反馈模式。

#### Scenario: 页面存在创建操作
- **WHEN** 页面支持创建用户、分组、对端或规则
- **THEN** 创建入口作为页面唯一或明确的主操作展示

#### Scenario: 行操作数量较多
- **WHEN** 单条记录存在多个低频操作
- **THEN** 系统保留高频操作并将低频操作收纳到明确的更多菜单中

#### Scenario: 执行危险操作
- **WHEN** 管理员删除、吊销、重建、停用或执行其他不可逆或高影响操作
- **THEN** 系统显示影响说明并要求明确确认，操作期间阻止重复提交

### Requirement: 统一页面状态反馈
系统 SHALL 为页面和局部区域提供一致的首次加载、刷新、空数据、无匹配结果、操作中、成功、失败和禁用状态。

#### Scenario: 首次加载数据
- **WHEN** 页面尚未取得展示数据
- **THEN** 系统显示加载反馈而不是空白区域或误导性的空数据文案

#### Scenario: 搜索没有结果
- **WHEN** 数据存在但当前筛选条件没有匹配项
- **THEN** 系统显示无匹配结果，并提供清除筛选或返回完整列表的入口

#### Scenario: 操作失败
- **WHEN** 页面操作抛出可处理异常
- **THEN** 系统保留当前上下文、恢复可操作状态并显示可理解的失败原因

### Requirement: 可复用交互的一致性
系统 SHALL 使复制、刷新、保存、取消、关闭、确认、分页和批量选择等通用交互在所有页面保持一致的行为和反馈。

#### Scenario: 复制数据
- **WHEN** 管理员复制链接、标识、地址或配置片段
- **THEN** 系统完成复制并显示简短成功反馈

#### Scenario: 在局域网 HTTP 页面复制数据
- **WHEN** 管理员通过非安全上下文的 HTTP 地址访问后台并触发复制
- **THEN** 系统使用随应用本地分发的兼容能力完成复制或给出明确的手动复制路径，不依赖 HTTPS、localhost 或外部 CDN

#### Scenario: 重复触发异步操作
- **WHEN** 一个异步操作仍在执行时管理员再次点击对应操作
- **THEN** 系统忽略重复提交，并持续显示当前操作状态

### Requirement: 浏览器交互优先复用现成能力
系统 SHALL 对剪贴板、滚动、焦点、拖拽和其他浏览器交互，依次优先使用 NiceGUI/Quasar、浏览器标准 API、现有本地开源库和经评估的新开源库；只有这些能力均不满足时才实现带测试的薄适配层。

#### Scenario: 框架已经提供交互能力
- **WHEN** NiceGUI 或 Quasar 已经提供满足需求的组件、方法或生命周期行为
- **THEN** 系统直接复用该能力，不再手工加载同类库或复制其实现

#### Scenario: 需要新增第三方浏览器库
- **WHEN** 框架、浏览器标准和现有本地依赖均不能满足交互需求
- **THEN** 系统选用固定版本的成熟开源库并随应用本地分发，同时记录来源、许可证、用途和完整性校验值

#### Scenario: 没有合适的现成能力
- **WHEN** 已记录的选型检查确认不存在合适的框架能力、标准 API 或开源库
- **THEN** 系统只实现职责单一的薄适配层，并通过自动化测试覆盖成功、失败和资源清理路径
