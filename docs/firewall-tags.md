# NiceVPN 标签体系与联动

## 数据模型

标签由 `tags`、`user_tags`、`group_tags` 持久化，关联表以联合主键和索引保证幂等。标签 ID 是稳定引用，名称仅用于展示。标签关联支持用户、组的单个和批量维护。

## 已支持的消费场景

### 中心防火墙

- 中心防火墙规则支持 `owner_type=tag`、`owner_id=tag UUID`。
- 标签不是地址快照。每次刷新时按当前直接关联用户、关联组、活动用户 CCD 地址和活动组 CIDR 重新计算。
- 标签源集合使用稳定的 `ovpntag_*` 名称，同一个标签被多条规则引用时复用一份 `hash:net` 集合，通过 stage/swap/rollback/gc 声明式收敛。
- 标签没有有效成员时不生成放行规则，不能退化成无源地址限制的 ACCEPT。

### 对端 Mesh 路由可见范围

- 对端的 Mesh 路由范围同时支持选择组和标签。
- 组与标签采用 **OR** 关系：用户命中任一已选组，或拥有任一已选标签，即可收到该对端 LAN 的 CCD push route。
- 标签包括用户直接关联的标签，以及其当前活动组继承的标签。
- 组和标签都不选择时，路由对所有活动用户下发。
- 停用用户会从 CCD 中移除 Mesh push route；重新启用时重新计算。已删除用户不再参与计算。
- 对端保存时会比较 LAN、组范围、标签范围的语义快照；仅标签范围变化也会触发 Mesh CCD 重算。

### 对端远端防火墙

- 对端远端规则的新建/编辑支持来源类型「标签」。
- 本地远端链缓存保存一条逻辑标签规则（tag ID、动作、协议、目标地址/端口），不保存创建时的静态源地址。
- 每次推送到对端时，NiceVPN 根据标签当前成员解析源地址，先折叠被组 CIDR 覆盖的单 IP，再展开为远端 iptables 规则；标签没有有效成员时不下发该规则，避免产生无源限制的 ACCEPT。
- 标签成员、用户状态/CCD 地址、用户切组、组子网或组状态发生变化时，会异步安排引用该标签的远端防火墙刷新。SSH 不可用或写回失败时，本地远端链缓存会持久化标记为待同步并记录错误；之后可在「防火墙 → 对端远端」手动推送重试。
- 远端标签规则目前按源地址展开为多条 iptables 规则，不依赖对端预装 ipset；标签成员很多时，远端链规则数量会随有效源地址数增长，后续可评估远端 ipset 后端。
- 为保护本地逻辑标签绑定，进入对端远端页面时，如果工作副本含动态标签规则，会跳过自动拉取。管理员手动点击「从对端拉取」时会二次确认；确认后将远端展开后的规则作为普通原始规则接管，本地动态标签绑定会丢失。

## 联动与生命周期

- 用户/组标签关联变化：刷新被引用的中心防火墙标签集合、相关 Mesh 路由和远端标签规则。
- 用户启停、切组、删除，以及组状态/子网变化：对相关标签规则和 Mesh 路由重新计算。
- 标签详情页分别统计中心规则与对端引用，并可查看引用它的 Mesh 路由/远端防火墙规则；“已引用”筛选包含两类规则。
- 删除标签时，如果仍被中心防火墙规则、对端 Mesh 路由范围或远端防火墙逻辑规则引用，会禁用删除入口并在服务层拒绝删除，提示先解除引用。
- 删除对端时，同时清理本地远端防火墙工作副本及 prepush 备份，避免遗留标签引用。

## 验收

1. 给用户直接关联标签、给组关联标签，分别确认中心防火墙源集合的成员。
2. 对端 Mesh 范围只选组、只选标签、组+标签混选；验证 OR 语义以及空选择=全部活动用户。
3. 停用用户，确认 CCD 中 Mesh route 块被移除；重新启用后恢复符合条件的路由。
4. 新建远端标签防火墙规则，确认推送时按当前标签成员展开源 IP。
5. 修改标签成员、用户状态/CCD IP、切组或组子网，确认远端规则自动刷新；模拟 SSH 失败，确认缓存显示待同步且错误可追踪。
6. 确认远端标签规则可编辑、停用、启用、删除和排序；手动拉取前会明确提示动态绑定将丢失。
7. 标签仍被中心规则、对端路由或远端规则引用时，确认删除被拒绝；解除引用后可删除。
8. 模拟中心 iptables 或远端 SSH 写回失败，检查中心回滚和远端 pending 状态。

测试机验收前先备份 `iptables-save`、`ipset save` 和远端对端 filter 链。
