# 安全与身份认证

## 设备绑定

系统设置支持三种模式：

| 模式 | 行为 |
|---|---|
| `weak_log` | 仅记录，不拒绝连接 |
| `weak_fingerprint` | 使用可用的设备指纹进行通用绑定 |
| `strict_hwaddr` | 必须提供硬件 MAC，否则拒绝 |

设备绑定豁免需同时打开全局开关，并在用户组或标签上配置。用户直接标签、所属组标签或组自身配置命中任一项即可。关闭全局开关只停用豁免，不删除原配置。

豁免只影响设备指纹检查，不绕过证书、用户状态或防火墙策略。

## 企业 SSO

### 配置

1. 在「系统设置 → 企业认证 → 统一认证」选择钉钉或企业微信，并填写对应应用凭证。
2. 钉钉填写一套应用 Client ID / Secret，并维护允许企业名单；企业微信填写 CorpId、AgentId 和 Secret。
3. 在身份提供商登记回调地址：`https://<域名>/auth/sso/dingtalk/callback` 或 `https://<域名>/auth/sso/wecom/callback`。HTTP 也可用于可信内网测试。
4. 在 NiceVPN 设置「认证地址」；留空时使用「系统设置 → 访问地址」中的首个 `domains` 地址。地址需包含协议和主机，可带端口，不要带路径。
5. 打开「开启认证」；按需打开「所有人生效」，否则在目标用户组或标签上开启 SSO。

### 企业名单与认证范围

- 钉钉名单每行填写 CorpId 或企业名称；两者都填时只按 CorpId 匹配。
- 仅填写企业名称时，NiceVPN 需要钉钉组织基础信息读取权限，并对服务端核实的名称做完全匹配；建议优先使用 CorpId。
- 企业身份由服务端 OAuth 响应核验。办公系统账号不需要存在于 NiceVPN 用户表，也不会改变 VPN 用户、组或防火墙权限。
- 全局总开关只启用 SSO 能力；全员开关或组/标签策略决定哪些证书必须登录。不支持 WebAuth 的客户端不能绕过强制 SSO，应使用未要求 SSO 的组或标签。
- SSO 成功的连接只记录设备信息，不执行设备绑定拒绝；未要求 SSO 的连接继续原设备绑定策略。
- 会话离线复用窗口为 1 小时；在线连接持续续期。企业白名单或应用配置变化后，旧授权不能绕过新策略。

## 部署安全

- 管理端 8880 不应直接暴露公网；API 和 OAuth 回调使用 8881。
- 公网登录应使用 HTTPS；HTTP 仅建议用于可信内网测试。
- OpenVPN Management Socket 仅允许本机受控访问。
- SSO 密钥文件为 `data/sso_provider_master.key`，权限应为 0600；备份时必须与 `data/nicevpn.db` 一起保存。
- 不记录 OAuth Code、Token、App Secret 或一次性认证事务凭据。
