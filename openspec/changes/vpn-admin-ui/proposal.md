# Proposal

## Why

VPN 管理后台已经覆盖初始化、监控、用户、分组、对端、防火墙、证书、服务和设置等完整运维流程，但页面各自维护大量重复样式和交互结构，单个主题文件已过度膨胀，继续逐页追加 CSS 会提高修改成本并造成视觉与行为不一致。现在需要在不拆分独立 Vue 前端的前提下，统一使用 NiceGUI、Quasar、AG Grid 和 ECharts 建立可复用的后台组件体系，并逐项迁移全部页面和子功能。

## What Changes

- 建立以 NiceGUI/Quasar 为基础的统一设计系统，集中管理主题色、暗色模式、尺寸、密度、状态色和组件默认属性，显著减少页面级 CSS。
- 建立可复用的页面外壳、标题栏、操作栏、状态标识、指标卡、空状态、加载状态、错误状态、确认对话框和异步操作反馈组件。
- 对数据密集页面按需采用 NiceGUI 内置 AG Grid 集成，统一搜索、筛选、分页、选择、批量操作、行操作和状态展示；简单列表继续使用 Quasar，避免过度复杂化。
- 使用 NiceGUI 内置 ECharts 集成完善仪表盘，展示服务健康度、在线用户、流量和告警等信息，并提供相关页面的快捷入口。
- 分阶段迁移导航布局、初始化向导、仪表盘、用户、用户组、对端站点与部署说明、防火墙中心与对端策略、证书、本机与对端服务、日志与配置编辑、系统设置各页签。
- 对所有页面和子功能建立独立的小任务与验收点；先完成共享组件和页面范式，再复用到结构相似的后续页面。
- 保留现有业务服务、数据模型、API、操作语义和危险操作确认规则；本次不拆分独立 Vue 工程。允许使用固定版本、随应用本地分发的成熟开源 JavaScript 库和少量浏览器适配代码，但业务规则继续留在 Python。
- 新增默认关闭的单管理员登录保护：仅当配置文件同时提供管理员用户名和密码哈希时启用；未配置时保持现有直接访问方式，配置不完整时启动即报错。
- 增加组件级、页面构建级和关键交互回归验证，覆盖空数据、加载、成功、失败、禁用和危险操作状态。

## Capabilities

### New Capabilities

- `vpn-admin-design-system`: 统一管理 VPN 后台的导航外壳、主题令牌、基础组件、响应式布局和交互状态。
- `vpn-admin-data-experience`: 统一管理后台中的 AG Grid 数据视图、ECharts 仪表盘、筛选分页、批量操作以及加载、空白和错误反馈。
- `vpn-admin-page-workflows`: 规定初始化、仪表盘、用户、分组、对端、防火墙、证书、服务和设置页面必须完整保留并呈现的操作入口与交互流程。
- `vpn-admin-auth`: 规定可选单管理员登录的配置开关、密码哈希、会话、路由保护、登录退出和错误处理行为。

### Modified Capabilities

无。仓库当前没有已注册的 OpenSpec capability；本次新增上述能力规格。

## Impact

- 主要影响 `script/py/vpn/main.py`、`script/py/vpn/app/ui/theme.py`、`script/py/vpn/app/ui/components/` 和 `script/py/vpn/app/ui/pages/`。
- 依赖层面继续使用 NiceGUI 3.18 系列提供的 Quasar、AG Grid 和 ECharts 集成；实施时需要核对实际安装包暴露的组件 API 和许可证边界，不引入独立 Node/Vue 构建链。
- 新增 `pwdlib[argon2]` 用于管理员密码哈希与验证；第三方浏览器库固定版本下载到本地并记录来源、许可证和校验值，不依赖 CDN。
- 现有 `app/services/`、`app/models/`、`app/api/` 和数据文件格式原则上不变；仅在页面迁移暴露出缺少可复用查询接口时进行最小抽取。
- 页面视觉、导航结构和列表呈现会发生明显变化，但既有 URL、业务含义、危险操作保护和运维结果保持兼容。
- 测试将扩展到共享组件、页面构建、AG Grid/ECharts 配置以及核心按钮和对话框流程。
